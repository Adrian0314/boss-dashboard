# BOSS 岗位看板

给 [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper) 做的本地可视化界面：一键拉取、实时筛选、结果看板。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | **单文件前端**，HTML + CSS + JS 全部内联，无外部依赖 |
| `server.py` | 本地后端，**仅用 Python 标准库**，无第三方依赖 |
| `启动.bat` | 双击启动并自动开浏览器 |
| `_e2e.py` / `_layout.py` / `_ai_test.py` / `_make_sample.py` | 开发期验证脚本，日常使用可删 |

## 使用

### 1. 启动看板

双击 `启动.bat`，浏览器自动打开 <http://127.0.0.1:8765>。关掉那个黑色命令行窗口即可停止服务。

### 2. 准备 Chrome 登录态（只需一次）

页面顶部会出现一张**黄色提示卡**：

> Chrome CDP 未启动 —— 抓取需要连接一个已登录 BOSS直聘的专用 Chrome。

点 **「启动 Chrome 并登录」**，会自动拉起一个**独立的 Chrome 窗口**（不影响你主 Chrome）。在那个窗口里扫码登录 BOSS直聘，登录态会长期保存，重启机器也还在。

提示卡变绿、「开始拉取」按钮可点后，就能正常抓取了。

> 也可以手动执行：`python scripts\boss_cdp_raw.py --setup-chrome`

### 3. 用

- **一键拉取**：填关键词 / 城市 / **目标条数** → 点「开始拉取」。执行日志实时滚动，完成后自动加载本轮结果。
- **全职/兼职**：抓取区可按用工类型过滤（全部/全职/兼职），由 BOSS 服务端过滤；结果带 job_type 字段，筛选区可二次筛选，卡片显示 🧕 徽章。
- **按条数抓取**：默认目标 60 条，达到即停；连续 3 页无新增也会停并提示实抓多少条。
- **详情页开关**：默认「不抓」只取列表；需要 JD 正文才切到「抓取」（逐条访问职位页，慢得多）。
- **实时筛选**：搜索框输入任意文字，职位名、公司、技能、标签、福利全部即时匹配，命中的词**黄色高亮**。
- **结构化筛选**：城市（**可多选**）、最低月薪、**经验**、**学历**、仅新增。
- **城市多选**：点「选择…」勾选多个城市；选中的以标签展示，点 × 单独移除；「全部」= 不限城市。抓取城市改动会自动勾选到筛选里。
- **浮动导航**：右下角常驻「↓ AI」跳到 AI 问答、「↑」回到顶部，滚动到底/顶时自动隐藏。
- **AI 全量分析**：默认发送全部筛选结果，不再截断前 60 条（可用 BDS_AI_MAX_JOBS 限制）。
- **排序**：薪资高→低 / 新增优先 / 职位名。
- **统计概览**：命中数、月薪均值与中位数、新增数；高频技能 chip **点击即可反填搜索**。
- **AI 数据分析**：基于**当前筛选出的岗位**直接提问，见下节。
- **AI 会话**：可新建 / 切换 / 重命名 / 删除会话，历史会话自动保存在浏览器本地，刷新不丢。默认沿用当前会话，随时可切。
- **输入记忆**：抓取参数、筛选条件、选中的结果文件都会记住，刷新/重开浏览器不丢。
- **收工**：提示卡上的「关闭 Chrome」可关掉专用浏览器（不影响主 Chrome）。

## AI 数据分析

页面底部的「AI 数据分析」面板可以针对**当前筛选结果**提问，例如薪资分布、技能要求、学历门槛、值得优先投的岗位。

### 开启方式

AI 功能通过 **OpenAI 兼容中转站**调用，三项配置全部由环境变量注入，仓库内不含任何服务商地址或密钥。

在同目录新建 `secrets.env`（已被 `.gitignore` 忽略）：

```ini
BDS_AI_BASE_URL=https://你的中转站地址/v1
BDS_AI_API_KEY=你的密钥
BDS_AI_MODEL=你的模型名
```

然后双击 `启动.bat` 即可（脚本会自动加载 `secrets.env`）。
也可以改用系统环境变量，两者等价、环境变量优先。

### 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `BDS_AI_BASE_URL` | 空 | **必填**，OpenAI 兼容中转站地址，需包含 `/v1` |
| `BDS_AI_API_KEY` | 空 | **必填**，中转站密钥 |
| `BDS_AI_MODEL` | 空 | **必填**，模型名，由你所用的中转站决定 |
| `BDS_AI_MAX_JOBS` | `60` | 送进模型的岗位条数上限 |
| `BDS_AI_MAX_TOKENS` | `8000` | 单次输出 token 上限 |

### 工作方式

1. 后端先在**本地算好统计结果**（薪资分档/中位数/高频技能/经验学历分布），连同岗位明细一起发给模型
2. 提示词明确要求模型**直接给结论、不做计算、不写代码**
3. 前端用受限的 Markdown 渲染（先转义再套标签，模型输出不会被当作 HTML 执行）

> **为什么要预计算**：推理型模型拿到原始数据会自己逐条算，思考过程可能吃掉全部 token 预算导致
> `content` 返回 null。预计算把「算」这一步交给本地代码，模型只负责「说」，回答快 4 倍且稳定。

## 配置

改路径编辑 `server.py` 顶部，或用环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BDS_REPO` | `C:\Users\zheng\Desktop\boss-zhipin-scraper` | scraper 仓库路径 |
| `BDS_RESULT_DIR` | `~/.boss-zhipin-scraper/job-result` | 抓取结果目录 |
| `BDS_CDP_PORT` | `9222` | Chrome 调试端口 |
| `BDS_PORT` | `8765` | 看板端口 |

## 设计说明

**为什么需要后端**：`file://` 打开的页面受浏览器同源策略限制，既不能执行本机 Python，也不能读取本地 JSON。所以「一键拉取」必须有一条数据通道。前端仍是单文件，后端只有标准库、无需安装任何东西。

**安全边界**：只监听 `127.0.0.1`（不对外网暴露）；文件名参数走白名单正则 + 路径归一双重校验，拒绝路径穿越；目标条数钳制在 1–500。

**数据源**：只读取 scraper 自己产出的 `boss_jobs_*.json` / `boss_details_*.json`，字段与 `map_api_job()` 完全对应，没有臆造字段。薪资条是从 `salary`（如 `30-60K·15薪`）解析下限后按相对值画的，不是绝对刻度。

## 已知限制

- **CDP 未启动时不能拉取**。页面顶部会显示红点并给出对应命令，但历史数据仍可正常浏览和筛选。
- **拉取需要真实 Chrome 在跑**，且受 BOSS 风控影响；遇到 `_security_check` 需人工处理（scraper 不会自动绕过）。
- 请仅用于个人求职分析，控制频率，遵守 BOSS直聘用户协议。
